Factory Inventory Management System

This is a demo with a Vue 3 single-page app and a stateless FastAPI service. The service loads JSON fixtures into memory when it starts and filters them for each request. There is no database, no authentication, and nothing is written back to disk.

System architecture

Data flow: changing a filter

  1. User selects a filter in FilterBar.vue The four controls are Time Period, Warehouse, Category, and Order Status. Each one writes to a module-level ref in useFilters.js. These refs live outside the composable function, so every view that imports them shares the same state.
  2. The view's watch() fires Each view watches only the filters that apply to it. Dashboard and Orders watch all four. Inventory, Demand, and Backlog watch only warehouse and category. Spending watches only the period.
  3. getCurrentFilters() builds a params object The UI's selectedLocation becomes warehouse, and selectedPeriod becomes month.
  4. api.js builds the query string and sends the GET request Filters set to 'all' are left out of the URL, for example /api/orders?warehouse=Tokyo&month=Q2-2025.
  5. FastAPI filters the in-memory lists apply_filters() uses an exact match for warehouse and a case-insensitive match for category and status. filter_by_month() does a substring match on order_date, or uses QUARTER_MAP for quarters. Inventory has no date field, so the period filter doesn't apply to it.
  6. The response is validated and returned as JSON Endpoints with a response_model are validated by Pydantic. The summary, spending, and report endpoints return plain dicts and are not validated.
  7. The view stores raw data in refs and derives everything else with computed KPIs, SVG chart geometry, and tables are computed properties. Currency is formatted with utils/currency.js: USD, or JPY at a fixed rate of 150 when the locale is ja.

Data model

InventoryItem

sku, name, category, warehouse, quantity_on_hand, reorder_point, unit_cost, location. Low stock means quantity_on_hand ≤ reorder_point.

Order

order_number, customer, items[], status, order_date, expected_delivery, actual_delivery?, total_value, warehouse, category. Dates cover Jan to Dec 2025.

Backlog, Demand, and PO

BacklogItem links an order to a SKU shortfall with a priority. DemandForecast stores current and forecasted demand with a trend. PurchaseOrder references backlog_item_id.

The fixture values are: warehouses San Francisco, London, and Tokyo; categories Circuit Boards, Sensors, Actuators, Controllers, and Power Supplies; order statuses Delivered, Shipped, Processing, and Backordered.

Things to know

Frontend calls endpoints that don't exist

/api/tasks and /api/purchase-orders are called from api.js but not implemented in main.py. Tasks fall back to the mock user in useAuth.js.

Hard-coded dates

QUARTER_MAP and /reports/quarterly only know about 2025. Data for other years is silently dropped from quarter filters.

Read-only and stateless

Every write path is missing. Restarting the server resets everything, and the fixtures are the only source of truth.

Backlog.vue is unrouted

The view exists but isn't registered in main.js. Backlog data appears only as a table on the Dashboard.

Inconsistent API access

Reports.vue imports Axios and repeats the base URL instead of using api.js.

Demo-grade security

There is no authentication and CORS allows every origin. The base URL is hard-coded, so the app won't work if it's deployed anywhere other than localhost.
